## Acceptance and verification contract

- Publish a self-contained `plugins/spec-driven-development` bundle containing
  ideate, build-author, pre-dev-prep, tdd, pr-author, merge-manager, close-milestone.
  Existing standalone skills and installed user settings remain unchanged.
- Carry scoped milestone authorization between phases; do not introduce seven
  confirmation gates. Preserve separate merge, deployment and human acceptance gates.
- Include shared workflow contracts, context/phase/review templates and independent
  reviewer instructions. Main owns implementation and completion; real independent
  reviewers own assessments. Missing review capabilities/evidence block readiness.
- Define screenshot requirements for UI changes, final-head review invalidation,
  and the required draft-to-ready transition. No UI is changed by this bundle.
- Provide local Python 3.11+ helpers for read-only branch inspection, package
  validation and preview-first milestone archival. No helper contacts GitHub,
  merges, deploys, installs a plugin, or authorizes its own mutation.
- Archive only explicitly declared completed milestone records after main has
  recorded completion, final-head independent sign-offs and required verification.
  Require matching HEAD, clean repository, safe paths and exact preview digest.
  Retain active directory structure, adjust supported relative Markdown links,
  refuse unsupported/ambiguous links, and roll back caught failures. Disclose
  concurrent-writer and crash-safety limits; digest is consistency, not authority.
- Tests use disposable real Git repositories and synthetic evidence. Demonstrate
  behavior red/green for helpers, validate all skill/package links and metadata,
  and independently forward-test realistic workflow scenarios. Do not claim tests
  prove model behavior, installation/discovery, real GitHub merge or a live trial.
- Deliver a reviewed GitHub PR with both distinct reviewers signed off on its final
  SHA, passing checks, accessible usage instructions and explicit reconstruction
  limits; mark it non-draft before notifying the owner. No automatic merge/install.
